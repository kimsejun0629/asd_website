# 항공기체 3D 쇼케이스 (aero · aero-en `#a3d`, `web/js/a3d*.js`)

3D 모델 · 연출 · 도장을 고칠 때 읽는다. 도장 실측값은 livery.md, 검사는 verify.md §4, 공용 루프 규칙은 motion.md.

## 1. 모듈과 불러오기

| 깊이 | 파일 | 내용 |
|---|---|---|
| 1 | `a3d.js` | 연출(스크롤 → 기종 · 회전 · 부위), 글꼴 대기, 텍스처 업로드 · 메모리, 대체 경로, `window.A3D` |
| 2 | `a3d-stage.js` | 스튜디오 조명 · 환경 반사 · 그림자, `createStage(canvas,{dpr})` → `.resize/.pivot/.fit/.view/.render` |
| 2 | `a3d-craft.js` | 기종별 형상 · 조립 · 제원(`airliner(P)` · `TYPES` · AH-6), export `build(key)` · `KEYS` |
| 3 | `a3d-geo.js` | 동체 로프트 · NACA 날개 · 회전체 등 형상 도구 |
| 3 | `a3d-paint.js` | 도장 · 텍스처: 팔레트 `KE` · 재질 `paint` · `M` · 동체 도장 캔버스 `livery` · 로고타입 · `wingMat` · `finPaint` · `taegeukTex` · `pack` |
| 3 | `a3d-sym.js` | 새 태극 도형 `drawSym` |

- three.js 0.169.0을 aero.html의 importmap으로 jsdelivr에서 받는다. `a3d.js`는 `type=module` + `onerror`(→ `a3-nogl`).
- craft는 sym을 쓰지 않아도 `import './a3d-sym.js'`로 깊이 3을 지킨다(깊이가 늘면 기체를 만드는 때 · 동체 글씨 글꼴이 바뀔 수 있음).
- **`a3d-paint.js`와 `a3d-craft.js`는 같은 게시에 넣는다.** paint가 없으면 모듈 그래프가 실패해 목록 대체 화면이 뜬다.
- **대체 목록 `#a3d.a3-nogl`로 바뀌는 경우:** importmap 미지원(바로) · WebGL 없음 · three.js CDN 실패 · 9초 안에 시작 못 함(타이머는 aero.html 인라인 ES5 스크립트). 목록 그림은 메인 스트립과 같은 `img/aero/top-<기종>-k26.webp`(AH-6만 `top-ah6.webp`).

## 2. 연출 (`a3d.js`)

- 장면 기준 길이 = 등장 `ARR .3` + 회전 `SPIN 1.6` + 부위마다 `PART 1.0` + 마무리 `EXIT .4`. 실제 스크롤은 부위마다 `0.6H`를 추가한다. 부위 진행 `.55~.98`에 5차 곡선으로 거리를 배분해 후반만 감속하며 완전 정지 없이 원래 속도로 이어진다. `C/TOT`는 장면 좌표, `DIST`는 실제 총 거리다. `distanceAt/sceneAt`으로 변환하고 `scrollYAt`을 바로가기·검증 도구가 함께 사용한다.
- **회전:** 정확히 한 바퀴(2π), 기체(holder)만 돈다. 등장 구간 절반부터 시작. 카메라 방위는 고정이고, 회전 중 고도가 최대 +0.17 rad 올랐다 돌아오며 거리가 최대 4% 가까워진다.
- **부위:** 첫 부위 방위는 첫 화면과 0.03~0.32 rad 차이의 같은 쪽이라 회전 뒤 방향이 거의 안 바뀌고, 카메라가 부위 상자로 확대된다(787 윙팁은 고도도 0.24 → 0.8 rad). 나머지는 크림색 X-ray, 부위는 금색, 설명선 하나.
- **폰(≤900px):** 설명선 없이 점 위 가운데에 번호 · 이름표(12px). 화면 가장자리 8px 안으로 `--sx`로 보정하고, 점이 화면 위 30% 안이면 아래로(`.dn`).
- 섹션 높이는 무대(100svh) 높이로 정한다(주소창이 접혀도 같은 스크롤 위치 = 같은 기종).
- 루프는 무대가 화면에 걸칠 때만 그리고, Lenis가 다시 켜질 때 `ka-lenis` 뒤로 줄을 선다(motion.md §4).
- **글꼴 대기:** 한진그룹체 Bold를 최대 2.5초 기다린 뒤 기체를 만든다(그동안 그리지 않음). 대체 글꼴로 만든 기체가 있으면 0.8초마다 확인하고, 도착하면 모든 기체를 버리고 다시 만든다.
  - WebKit은 swap 글꼴이 오는 중에도 `document.fonts.check`가 true라 이 경로가 돌지 않는다(원래 동작). 그래서 글꼴 도착 전(`document.fonts.status`≠loaded)에는 원본과 같은 때(i+1, 80ms 뒤)에만 만든다. 만드는 때가 바뀌면 동체 글씨 글꼴이 달라진다.
- **메모리(아이폰 탭 종료 방지, v59):** WebKit은 텍스처로 쓴 캔버스마다 원본 · 업로드 사본을 따로 들고 있어 여객기 한 대가 약 0.5GB였다(마지막 기종에서 3GB 초과, iOS 한도 약 1.5GB).
  - 보이는 기체는 첫 그리기 뒤, 이웃(i+1 → i−1)은 한 작업에 텍스처 한 장씩 GPU에 올리고, 다 올리면 캔버스를 0×0으로 비운다(`up`). 글꼴 전에 만든 기체(`A.pre`)는 원본처럼 캔버스를 둔다.
  - 컨텍스트를 되찾으면 캔버스를 비운 기체는 새로 만든다.
  - 요철 · 거칠기 · 금속 맵은 셰이더가 읽는 채널(.r · .g · .b)만 한 텍스처로 합친다(`pack`, multiply · lighter 합성 — 픽셀을 읽어 오지 않음).
  - 기체는 버리지 않는다(버리면 되돌아갈 때 끊기고 늦은 글꼴에서 글씨가 달라짐). WebKit 최고치 3.3GB → 약 1.2GB, 화면은 원본과 같음(`_verification/perf/`).

## 3. 모델 (`a3d-craft.js` · `a3d-paint.js`)

- 기종 키: `787`(787-9) · `737`(737-8) · `a320`(A321neo) · `a330`(A330-900neo) · `a350`(A350-900) · `ah6`(AH-6i). 글로벌 6500은 제외(되살리지 않음).
- 치수는 기수 끝에서 뒤로 잰 거리 `s`(m)로 적고 모델 좌표 `x = x0 − s`로 바꾼다. 여객기 제원 키 전체는 `function airliner` 바로 위 스키마 주석에 있다.
- **불변 조건:** 기종의 `beats` 순서 · 개수 = aero(-en).html 그 기종의 `.pl li`(a3d.js가 번호로 짝지음). `beats`는 부위별 카메라(yaw · el · 상자 · 여유 배율).
- **동체 도장(`livery`, paint):** 캔버스 텍스처, 가로 = s, 세로 = 둘레 각. 이음매(오른쪽 옆면)를 넘는 그림은 한 번 더 그린다.
- **로고타입:** `liv.word{s0,ratio?,cap?,y?}`, s0만 필수. 기본 ratio 6.1 · cap 0.38×동체 높이(표면 호 길이) · y 창문 줄. A330만 cap 2.35 m · y .27.
- **꼬리 태극:** `finPaint`가 수직꼬리 표면 텍스처에 직접 칠한다. 기종별 `logoP{D,U,gap}`(기본 D .5 · U .4 · gap .02, craft의 `airliner`).
- **AH-6:** 군용 올리브 도장 캔버스는 `TYPES['ah6']` 안(craft)에 있다.
